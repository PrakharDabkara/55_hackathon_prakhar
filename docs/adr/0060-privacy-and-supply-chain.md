# ADR-0060: Privacy and the supply chain

Status: accepted. Builds on ADR-0020 (the provider port), ADR-0021 and ADR-0024 (the customer's text is data), ADR-0030 (photos), ADR-0054 (the account) and ADR-0059 (hardening).

## Context

After SEC1 and SEC2 four things were still open: nothing stopped a phone number, address or coordinates from reaching the model by a future change (free-tier prompts may be reviewed by Google); the only text a shop writes that a model reads, its name, went in as plain JSON; log lines had never been checked for personal data; and a login could not be ended everywhere. The dependencies and the CI actions had not been looked at.

## Decision

1. **A guard in the Gemini adapter, the only place the model is called.** Before every `generateContent` and `embedContent`, the system prompt, the conversation (tool results included, thought signatures left out) and the embedding texts are checked for: a 10-digit phone (also with `+91`, `91`, `0` in front, or written `98765 43210`), an email, a latitude and longitude pair, or a key that holds contact, home or location (`address`, `addressLine1`, `lat`, `lng`, `phone`, `email`, `userId`, `pincode`, ...). A hit throws `PrivacyGuardError` before the request leaves, and logs the call's purpose and the reason, never the text. UUIDs are cut out first (a UUID tail can look like a number). It is an `InvalidOutputError`, so the client never retries it and it does not count toward the circuit breaker (a customer typing a number must not switch the model off for everyone); callers see the same `AiUnavailableError` as any outage and degrade as before (a search falls back to the dictionary and trigrams, a new item fails closed).
2. **What reaches the model, traced.** Resolve and list lines: the customer's text (100 characters, one line) and catalog names. Item check: the item name. Errands: the task, the customer's answers and the budget; tool results with item names, shop id, shop name, distance, price, freshness, request state and counts. Nothing carried a user id, phone, address or coordinates (`where`, `userId` and the address id never leave the executor), so no code was removed; the guard is the lock for the future. A customer who types their own number into a search or task is blocked.
3. **Shop text is quoted data.** A shop name is the only shop text a model reads (order notes and the shop's "Other" replies go to people, never to a model; `errandPrivacy.int.test.ts` pins the fields a shop is shown with). It reaches the model as `<<<SHOP name SHOP>>>`: one line, control characters and the marks themselves removed so it cannot close its quote, phones/emails/coordinates replaced by `[removed]` (so a shop cannot make the guard block a customer's errand by putting a number in its name, or smuggle one in), capped at 60 characters. The system prompt names the marks and says never to obey what is inside. The plan and the shop screens still show the real name; only the model's copy is wrapped. Three dev eval cases (`d24` to `d26`, kind `injection`) give every synthetic shop an instruction in its name (English, Hinglish, and a closing mark); the case field is `shopNameSuffix`, the harness puts the names back. The holdout file was not touched.
4. **Uploads (checked, tests added).** Every photo and logo is decoded and re-encoded by `sharp` (JPEG, or WebP for a logo): EXIF, GPS, XMP, ICC and IPTC are dropped, orientation is applied first, magic bytes decide the type, 400 KB and 26 megapixels are the limits. Served with the stored type, `nosniff`, `Content-Disposition: inline`, and `private, no-store` (logos: public and immutable by the shop's choice). New tests: the bytes served over HTTP carry no GPS, and a WebP and a PNG with EXIF come out clean. **Not owner-only, on purpose:** a customer's request photo is seen by its owner and the shops that request went to, a shop's answer photo by that shop and the customer who asked, an unattached photo by its owner alone, everyone else gets 404. The shop cannot answer "is this the one?" without seeing the picture, so owner-only would end the feature; the rule stays as ADR-0030 wrote it, and a test already walks it.
5. **Logs.** One `createLogger` (`apps/api/src/logger.ts`) for the server: JSON lines with a redaction list (`phone`, `otp`, `token`, `authorization`, `cookie`, `address`, `addressText`, `q`, `query`, `text`, `task`, `note`, `lat`, `lng`, at the top and one level down), and an error serializer that drops what a Postgres error quotes (`detail`, `where`, `parameters`) and cuts phones and emails from the message. The request line carries the path only (no query string). The masked phone is logged as `phoneMasked`. `logging.int.test.ts` runs two logins, a request, an answer, an order with an address and a note, a search and a logout, and checks that the output holds none of the phones, tokens, codes, the address, the note or the search text, and that every request line has an id.
6. **`POST /account/logout-all`** (any role, no body). In one transaction it ends every session of the user and removes every push subscription (those devices are logged out); then it closes the user's open `/events` streams on every API instance (a `session.ended` event over Redis; without Redis, the local streams). A stream ticket is also refused if the user has no live session, so a ticket asked for just before cannot open a stream after. Customer Account has "Log out on all devices" with an in-app confirm sheet; the shop app has it at the bottom of Shop settings (its account area) with the same confirm. If the call fails, the app says so and stays logged in: it never claims it logged out when the server may not have.
7. **Supply chain.** `npm audit --omit=dev`: 0 vulnerabilities, nothing to fix or defer. gitleaks v8.18.4 over every ref (428 commits): 7 hits, all one rule (`generic-api-key`) on the same line, the `auth:` value of a fake push subscription in four test files (`push`, `lists`, `listPush`, `listPickup` int tests; commits 11d7dc6, a118bd6, 1177de0, 5c0f35e), the sample value from the Web Push documentation, never a credential. No rotation is needed. Every `uses:` in `ci.yml` and `evals.yml` is pinned to a commit SHA with its version in a comment (`actions/checkout`, `setup-node`, `cache`, `upload-artifact`); `evals/actionsPinned.test.ts` fails on a tag.
8. **`SECURITY.md`**: how to report, what we keep, and the limits of demo mode.

## Alternatives rejected

- **Asking a model to find personal data.** It would send the data to a model to decide whether to send it.
- **Blocking any run of digits.** Prices, quantities and barcodes are digits; the phone rule needs ten, or the prefixed forms.
- **Closing a user's streams on a single logout.** A stream belongs to the user, not a session, so it would also cut the user's other devices; it needs the session id in the ticket. A stream carries only ids as hints. Left as in ADR-0059.
- **Owner-only photos** (item 4).
- **A gitleaks job in CI, Dependabot, `helmet`.** Not asked for and not in the brief; the pins are what the task named.

## Consequences

- The agent's system prompt changed (the shop marks): the agent dev eval must pass before merge (`gh workflow run evals.yml -f suite=agent -f set=dev -f model=fallback`). Not run from here (it spends the shared eval quota); see the PR.
- A search that contains a phone number or an email gets no model help (dictionary and trigram only). A label such as `address:` or `phone:` in a query blocks it the same way.
- Logging `text`, `q`, `query`, `note` and the rest under those names is now silently `[Redacted]`; use another key for a count or an id.
- Logging out everywhere also forgets the alerts of every device; the person turns them on again after the next login.
- Scripts and the simulator still use their own plain `pino` (operator tools, warn level); only the server uses `createLogger`.
