# Failure modes: assumed vs observed (PR F1)

Every fallback or error branch should rest on a real response, not a guess. This lists each external
failure we branch on, what we assumed, what a real trigger or log showed, and whether the code matches.
Nothing here was fixed in PR F1: tests, fixtures and this page only. Fixes are in "Bugs found".

**Confidence:** _observed_ = a real response, kept in `apps/api/src/testing/observed/`; _documented_ =
from a vendor page, not seen here; _guess_ = no evidence. **Match:** yes / no / unknown.

Evidence files (`apps/api/src/testing/observed/`):

- `gemini-ci-dev-errors.json`: 109 failed Gemini calls from 16 CI dev eval runs (our `AI call failed` log lines: status, Google's status word, a 160-character message. Raw bodies and headers were never logged).
- `redis-oom.json`, `redis-down.json`, `postgres.json`: recorded by `scripts/probe/record-local-failures.ts` against throwaway Redis 8.8.3 and Postgres 17 containers.
- `gemini-429-*.json`, `gemini-free-*.json`: **not yet captured**. Written by `scripts/probe/gemini-quota-probe.sh` and `gemini-free-triggers.sh`, which the owner runs with the evals key. The contract tests that replay them switch on when the files exist.

## Bugs found

Ranked by judge-day impact. Each is the smallest fix, not done here.

1. **Daily 429 versus per-minute is unverified.** The only real 429 we have says "exceeded your current quota", with no sign it is daily. If Google's daily 429 reaches us without a `PerDay` quota id (some 429s carry no details at all), every search retries, waits and fails slowly until the breaker opens. _Fix:_ run the probe, then (a) match the real quota id, and (b) when a 429 has no `retryDelay`, retry once only.
2. **Redis full is silent for a seeker.** The errand path ends `queue_unavailable`, but a new request's fan-out failure is only a warning (`requests/pinging.ts`): the request exists, nobody is pinged, and the seeker waits until expiry. The sweeper also needs `queue.add`, which is refused while full. R1's job retention makes this unlikely. _Fix:_ none beyond R1; add `/admin/health/details` `usedMemoryBytes` to the judge-day pre-check (done in `release-check.sh`).
3. **Demo seed/reset can crash the API.** `demo/service.ts:64` holds a checked-out client for the whole run with no `error` listener. If Neon drops that connection mid-run, pg emits `error` on it and Node throws. Observed with Postgres 17. _Fix:_ the same listener as `queryable.ts:23`. Test `modules/demo/connectionLoss.int.test.ts` is marked `it.fails`; remove `.fails` with the fix.
4. **No database timeouts.** No `connectionTimeoutMillis`, `statement_timeout` or `query_timeout`, so a suspended or slow Neon compute makes a request wait, not fail. _Fix:_ `connectionTimeoutMillis: 10_000` and `statement_timeout` (for example 15 s) in `db/pool.ts`.
5. **Push sends have no timeout.** _Fix:_ pass `timeout: 10_000` to `sendNotification`.
6. **Browser calls have no timeout, and a dead network is a `TypeError`.** _Fix:_ `AbortSignal.timeout(30_000)` in `createCaller` and map `TypeError` to `ApiError(0,'network')` as photo upload already does.
7. **Map tiles fail silently.** _Fix:_ a `tileerror` handler showing a short note.

## Assumptions still a guess

Gemini 4xx shapes (invalid key, unknown model, oversize input) and the raw 429 body until the probes run; SDK `AbortError`; web-push status codes other than the documented 404/410; push-service hangs; Render cold start and 502 pages; SSE across Render's proxy; OSM tile refusals; how Neon's quota suspension appears at the `pg` level.

## Run the probes

```sh
scripts/probe/gemini-free-triggers.sh                       # invalid key, unknown model, oversize input (no quota)
scripts/probe/gemini-quota-probe.sh gemini-2.5-flash-lite   # at most 25 tiny calls, evals project key only
```

Both read the key with `read -rs`, never print it, and write redacted files to `apps/api/src/testing/observed/`. Read them before committing. Record the local failures again with `node scripts/probe/record-local-failures.ts` (needs Docker).
