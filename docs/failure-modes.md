# Failure modes: assumed vs observed (PR F1)

Every fallback or error branch should rest on a real response, not a guess. This lists each external
failure we branch on, what we assumed, what a real trigger or log showed, and whether the code matches.
PR F1 added tests, fixtures and this page only. PR R2 (ADR-0065) fixed items 1, 2, 4 to 8 below; 3, 9 and 10 are in "Future".

**Confidence:** _observed_ = a real response, kept in `apps/api/src/testing/observed/`; _documented_ =
from a vendor page, not seen here; _guess_ = no evidence. **Match:** yes / no / unknown.

Evidence files (`apps/api/src/testing/observed/`):

- `gemini-ci-dev-errors.json`: 109 failed Gemini calls from 16 CI dev eval runs (our `AI call failed` log lines: status, Google's status word, a 160-character message. Raw bodies and headers were never logged).
- `redis-oom.json`, `redis-down.json`, `postgres.json`: recorded by `scripts/probe/record-local-failures.ts` against throwaway Redis 8.8.3 and Postgres 17 containers.
- `gemini-3.6-flash__*.json`, `gemini-2.5-flash*__404-*.json`, `*__invalid-key__*.json`, `*__unknown-model__*.json`, `models__list__*.json`: raw status, headers and body from `scripts/probe/*.sh`, run with the evals key on Oct 24 (free tier). Named `<model>__<kind>__<timestamp>.json`, never overwritten. Replayed by `modules/ai/observedFailures.test.ts`.

## Bugs found

**Status after R2:** fixed 1, 2, 4, 5, 6, 7, 8 (the `.fails` pins were removed with each fix); 3, 9, 10 are in Future.

Ranked by judge-day impact. Each is the smallest fix, not done here. Observed bugs are pinned by an `it.fails` test, which turns red when the fix lands: remove `.fails` then.

1. **A retired or renamed primary model has no way out.** Google answers 404 "no longer available to new users" (observed for `gemini-2.5-flash` and `-flash-lite`) while still listing them, so a name that worked can stop working. A 404 is neither retried nor sent to the fallback, so every AI call fails until someone changes the env var. Today every model in our config exists and is not flagged (checked against the list on Oct 24). _For R2:_ treat a not-found or retired 404 on `GEMINI_MODEL` as permanently unavailable, switch to `GEMINI_FALLBACK_MODEL` for the process, and log an error once. _Now:_ the weekly `/admin/ai/ping` check in the runbook shows `status: 404` at once. Pinned: `observedFailures.test.ts`, "a retired primary falls back".
2. **Demo seed/reset can crash the API.** `demo/service.ts:64` holds a checked-out client for the whole run with no `error` listener. If Neon drops that connection mid-run, pg emits `error` on it and Node throws. Observed with Postgres 17. _Fix:_ the same listener as `queryable.ts:23`. Pinned: `modules/demo/connectionLoss.int.test.ts`.
3. **Redis full is silent for a seeker.** The errand path ends `queue_unavailable`, but a new request's fan-out failure is only a warning (`requests/pinging.ts`): the request exists, nobody is pinged, and the seeker waits until expiry. The sweeper also needs `queue.add`, which is refused while full. R1's job retention makes this unlikely. _Fix:_ none beyond R1; `release-check.sh` already warns on Redis memory.
4. **The retry pause is shorter than the wait Google asks for.** A per-minute 429 said `retryDelay: 56s`; `MAX_PAUSE_MS` caps the pause at 30 s, so the retry lands inside the window and fails again, three times. _Fix:_ when `retryDelay` is above the cap, do not retry (go to the fallback model); or raise the cap past 60 s for background work only.
5. **No database timeouts.** No `connectionTimeoutMillis`, `statement_timeout` or `query_timeout`, so a suspended or slow Neon compute makes a request wait, not fail. _Fix:_ `connectionTimeoutMillis: 10_000` and `statement_timeout` (for example 15 s) in `db/pool.ts`.
6. **An input above the tokens-per-minute limit is retried.** On the free tier an oversize input is a 429 (`GenerateContentInputTokensPerModelPerMinute-FreeTier`, 250,000 tokens), and one request over the limit never succeeds. _Fix:_ treat a quotaId with `InputTokens` as not retryable. Pinned: `observedFailures.test.ts`.
7. **Our logs hide what the 429 says.** CI logs looked detail-free only because we log the 160-character message, not the details. _For R2:_ log `quotaId` and `retryDelay` on every 429.
8. **Push sends have no timeout.** _Fix:_ pass `timeout: 10_000` to `sendNotification`.
9. **Browser calls have no timeout, and a dead network is a `TypeError`.** _Fix:_ `AbortSignal.timeout(30_000)` in `createCaller` and map `TypeError` to `ApiError(0,'network')` as photo upload already does.
10. **Map tiles fail silently.** _Fix:_ a `tileerror` handler showing a short note.

## Future (out of scope for R2)

- **Redis full, silent fan-out** (item 3): unlikely after R1's job retention. `release-check.sh` warns.
- **Browser fetch timeouts and `TypeError` as a dead network** (item 9).
- **Map tile failure UI** (item 10).
- Failover state is per process: an eval run or script does not share what the API learned.

## The Gemini free-tier 429s, as observed (`gemini-3.6-flash`, Oct 24)

All three: HTTP 429, `error.status` `RESOURCE_EXHAUSTED`, a `details` array of Help, QuotaFailure and RetryInfo, and no `retry-after` header (the delay is only in `RetryInfo.retryDelay`, a string like `"56s"`). Headers seen: `x-gemini-service-tier: standard`, `content-type`, `date`, `server-timing`, no rate-limit headers. The `violations[]` entry names the limit:

| Limit               | `quotaId`                                              | `quotaValue` | `retryDelay`             | What it means                                        |
| ------------------- | ------------------------------------------------------ | ------------ | ------------------------ | ---------------------------------------------------- |
| Requests per minute | `GenerateRequestsPerMinutePerProjectPerModel-FreeTier` | 5            | 56 s                     | Wait about a minute                                  |
| Input tokens/minute | `GenerateContentInputTokensPerModelPerMinute-FreeTier` | 250000       | 26 s                     | One request is too big: retrying cannot help         |
| Requests per day    | `GenerateRequestsPerDayPerProjectPerModel-FreeTier`    | 20           | 6579 s (at 05:10:20 UTC) | Seconds to the reset: 07:00:00 UTC, midnight Pacific |

The daily limit of 20 was enforced at call 24 (Google's counting is loose). `ListModels` lists retired models, so a list is necessary but not sufficient.

## Assumptions still a guess

SDK `AbortError`; a Gemini 5xx other than 503; web-push status codes other than the documented 404/410; push-service hangs; Render cold start and 502 pages; SSE across Render's proxy; OSM tile refusals; how Neon's quota suspension appears at the `pg` level. The Gemini 4xx shapes and all three 429s moved from guess to observed.

## Run the probes

All with the evals project key (never production), read with `read -rs`. Files go to `apps/api/src/testing/observed/`, are redacted, and are never overwritten. Read them before committing.

```sh
scripts/probe/gemini-list-models.sh                   # models, which ones we use, any missing or flagged
scripts/probe/gemini-quota-probe.sh <model>           # at most 25 calls on an unused model with a small daily limit
scripts/probe/gemini-free-triggers.sh <model>         # invalid key, unknown model, oversize input
grep -rnE "AIza|AQ\." apps/api/src/testing/observed  # leak check: must print nothing
```

Record the local failures again with `node scripts/probe/record-local-failures.ts` (needs Docker). `.gitleaks.toml` adds the `AQ.` key format to the default rules; run it on the git history only (see the file).
