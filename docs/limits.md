## Operating rules for judging days

1. **No eval runs.** Evals use Gemini Project 2, so they do not spend production quota, but they keep the laptop runner busy and a merge or deploy restarts the API (cold start) and gives every visitor a new JS bundle (about 190 KB).
2. **No merges or deploys on judging days.** A deploy runs `ai:embed-catalog`; freeze from Nov 4.
3. **Demo `reset`/`seed` is safe for quota**: it makes no Gemini call (the demo module has no AI client, checked in `modules/demo/service.ts`) and touches no embeddings. It is not safe during a session: reset deletes demo users' requests, orders and learned stock. Run it before the first judge, never between.
4. **Quota reset time.** Gemini daily quotas reset at midnight Pacific: **12:30 IST until Oct 31, 13:30 IST from Nov 1**. A morning session therefore shares the bucket with the previous afternoon and evening. Run reset/seed and the warm-up after the reset, and check AI Studio before the first judge.
5. **Warm the cache.** Run each demo query once (one Find, one list, one errand) before judging. Answers are cached in Postgres (`writeCache`), so a repeat costs no AI call.
6. One judge, one demo phone. Do not share a login.

## Embeddings: what made about 1,000 calls in a day

**Facts from the code**

- Catalog vectors are stored in Postgres (`items.embedding`, pgvector) with a hash of `model|text`. Seeding does not touch them, so they are **cached and reused**. Only an item whose names or synonyms changed, or a new embedding model, is embedded again (`embedCatalog.ts`). The catalog has 280 items.
- Bulk embedding paths: `npm run ai:embed-catalog` (the deploy job, run after every merge to `main`; also by hand), and the eval runs (their own project and a vector cache). 50 texts per call, 1 s between calls, so a 280-item pass is about 6 s: **over 100 requests in one minute if each text counts**. That is the only code path that can produce the 100 RPM peak.
- Query embeddings: 1 text per uncached Find that gets past the dictionary, trigram and default steps; N texts per list. A Find never sends more than one.
- `scripts/demo.sh reset && scripts/demo.sh seed` make **0 embedding calls** (and 0 Gemini calls): the demo service has no AI client and the seed upsert leaves embeddings alone. The simulator, the autopilot, the MCP server and start-up jobs make none either.
- When the embedding call gets a 429: the client retries once (per-minute) or gives up (per-day), the Find catches `AiUnavailableError` and **carries on without embeddings**: the chat step runs with a trigram-only shortlist (fewer correct matches, one more chat call, no error). A list does the same. Nothing returns an error to the user.

**What we cannot see from the code.** Eight merges to `main` on Oct 23 each ran the catalog embedding, but each should only embed changed items, so deploys alone do not explain about 1,000. The likely sources are a catalog or synonym change that re-embeds many items on several deploys (a 429 mid-run is retried and counted again), a manual `ai:embed-catalog` or smoke run with a key from this project, or a local database reset followed by `ai:embed-catalog` (280 each time). **Prakhar to confirm** with this read-only query on the production database:

```sql
SELECT date_trunc('hour', created_at) AS hour, purpose, outcome, count(*) AS calls
  FROM ai_calls
 WHERE purpose LIKE 'embed%' AND created_at > now() - interval '7 days'
 GROUP BY 1, 2, 3 ORDER BY 1 DESC;
```

`embed_catalog` rows are batches of up to 50 texts. Compare the sum with 994. If `ai_calls` shows far fewer, the rest came from outside the deployed app (a laptop using this key).

**Bulk-embedding actions a judge-day could trigger:** none from a user. Only a deploy (merge to `main`) or a person running `ai:embed-catalog` or an eval with the production key. The first is covered by the freeze; the second by never using the production key locally.

**Fixes that need code:** a fallback model for embeddings (also needs vectors from one model only, so it means a second column and a re-embed); a per-day budget guard in `embedCatalog` that stops before 80 % of the quota.
