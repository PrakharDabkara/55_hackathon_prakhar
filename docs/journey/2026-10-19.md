# 2026-10-19 · Day 16, PR G: Le liya? and Aaj ki maang

- **What:** migration 020 (`pickup_visits`, `shop_stock.customer_verified_at` and `wrong_reports`), modules `pickups` and `demand`, three stock functions in `shops`, a `pickup_ask` push and `remindPickups`, `PICKUP_ASK_AFTER_MINUTES`, web `PickupAsk` and `ShopDemand`, "Raasta" noting on results and plans, ADR-0035, e2e at 360 px for both.
- **How:** Red commit first (API integration, unit, web, e2e), then the API, then the web. Privacy is enforced where the data is made: `HAVING count(DISTINCT user_id) >= 3` in the query, and the stock row has no customer column at all.
- **Why:** The answer is applied to (shop, item) and the customer stays in a table the shop cannot reach. Rejected: telling the shop "2 customers reported you", because with few customers that points at a person.
- **Learn:** Put the privacy rule in the lowest layer that can enforce it. A minimum group size checked in the UI can be bypassed by any other caller; in the SQL it cannot.
