## Day 17, PR H: understanding follow-ups (ADR-0036)

- **What:** "Kya aapka matlab…?" before any ping (`resolveForCustomer`, `Search.tsx`); modifier-only matches rejected (`modifierOnly.ts`); `ambiguous` words in the catalog file; wrong-report shops re-pinged (migration 021, `pings.ts`); plan honours pickup reports (`optimiser.ts`, `plan.ts`); ticked items at medium confidence (`classify.ts`, errand state); multi-select prompt; label fixes; 11 dev eval cases.
- **How:** Red tests first (one commit), then the code. The "phool" bug was found by following the candidates: the broom's synonym "phool jhadu" put it in the embedding and model shortlists. The re-ping bug was found by asking who else decides "ask this shop": the Redis dedupe window, not the learned-stock filter.
- **Why:** Fix the shape of the problem (a term whose last word is a product by itself), not the word "phool". Remember the report in the database (`invalidated_at`) because the API has no Redis. Rejected: a blocklist of words, and asking for every search.
- **Learn:** A cache or a window that protects against duplicates (the ping dedupe) can also protect a wrong state. When you hide an answer, ask which other layer still remembers it.

## Day 17, PR I: clean-up before the UI overhaul (ADR-0037)

- **What:** a server guard for identical tool calls (`executor.ts`, `conversation.ts`); d18 and resolve-dev fixes (`resolve.ts`, `resolvePrompt.ts`, prompt, seed v7); errand-only push suppression (`notifier.ts`); e2e uniqueness (`e2e/unique.ts`, scenario `{{kit}}`); the errandPatience race; richer agent eval report.
- **How:** read both CI reports (dev rows only), then wrote red tests for each guard before the code. The flaky test was found by reading the waker: state flips before the job is queued.

- **Learn:** an eval report that only says "failed" cannot be acted on. Record the evidence (which item, what the plan held) next to the verdict.
