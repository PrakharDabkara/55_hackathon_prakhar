## Evals workflow: fail fast on quota, run on a schedule, pin the runner

- **What:** `evals.yml` runs daily at 08:30 UTC, on the label and by hand (no push to `main`), 30-minute timeout; `modules/ai/quota.ts` (`rateLimitInfo`, `QuotaWatch`, `watchProvider`) + `ProviderError.rateLimit` set by the Gemini adapter; `evalResolveMain.ts` preflights and stops with `QUOTA_EXHAUSTED` (exit 3); all jobs on `ubuntu-24.04`, actions on Node 24 majors; runbook, ADR-0022 note, evals.md, changelog.
- **How:** test commit first (classification of Google's 429 body, the watch's rules, the adapter), then the code. The action versions came from the actions' releases and the `runs.using` line of each `action.yml`, not from memory.
- **Why:** a run that cannot finish should say so in seconds. I put the check in a provider wrapper so every call (resolve, errand, embedding) is seen without touching the retry client. Rejected: stopping on any 429, because per-minute 429s are normal and clear on their own.
- **Learn:** a free quota has windows (minute, day); retrying only helps when the wait is shorter than the window. Read which window was hit before deciding to retry.
