## PR A3: flake-hunter subagent and two flaky tests

- **What:** `.claude/agents/flake-hunter.md` (read-only: Bash, Read, Grep, Glob); test-only fixes in `apps/api/src/modules/push/notifier.int.test.ts` and `apps/simulator/src/simulate.int.test.ts`; `docs/ai-tooling.md`, CHANGELOG.
- **How:** two flake-hunters ran in parallel, one per test, each with its CI evidence. Both found a race, not a product bug. Notifier: the handler counts waiting pings when it runs, so the second search could land first; the test now awaits `idle()` between searches. Simulator: the API stores an answer before the simulator logs it; the test now waits until the log and counter catch up with the rows. Proof: each test 30/30 alone and 5/5 under 12 busy loops.
- **Why:** wait for a condition, never a longer sleep. Rejected: a bigger fixed window (still a guess under heavier load) and changing the notifier to count at ping creation (a product change nobody asked for; "and 1 more" is true when two pings wait).
- **Learn:** a subagent has its own context and tools, so a long repeat-and-measure loop costs the main session only the report. Its limit is that it starts cold. Also, neither hunter reproduced the flake locally: a diagnosis from code that fits the CI message is a hypothesis, and the fix is only proven to be harmless, not shown to cure.

## PR A2: project skills

- **What:** `.claude/skills/{askbuy-pr,askbuy-evals,askbuy-ui,askbuy-adr}/SKILL.md`, `askbuy-evals/run-evals.sh`, `skills.test.ts`, `run-evals.test.ts`, `vitest.config.ts`, a leaner `CLAUDE.md`, `docs/ai-tooling.md`, CHANGELOG.
- **How:** tests first in their own commit (frontmatter check; the script against a stubbed `gh`: id from the URL, no id fails, waits for completed, two evals in order, stops after a failure). Then the script and skills, then `CLAUDE.md` trimmed: procedures out, rules kept, one pointer per skill.
- **Why:** a procedure that only some tasks need should not sit in every session. Rejected: moving the hard rules (secrets, git, privacy) into skills, because a skill may never load and the hooks only catch some slips; and `yaml` as a test dependency (not in the brief), so the test reads our small frontmatter subset itself.
- **Learn:** progressive disclosure: a skill costs a one-line description every session and its body only when used, while `CLAUDE.md` is paid in full every time. Put what is always true in `CLAUDE.md`, what is sometimes needed in a skill.
