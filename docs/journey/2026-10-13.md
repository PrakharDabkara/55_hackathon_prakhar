## Day 2 CI and data

- **What:** Postgres (PostGIS + pgvector) and Redis in `docker-compose.yml` with `infra/postgres/Dockerfile`; SQL migrations for extensions and `shops` (GiST index); ADR-0007; `findShopsWithinRadius` with a Testcontainers test; `.github/workflows/ci.yml`, `.nvmrc`, `tsconfig.json`; `db:*`, `typecheck`, `test:unit`, `test:integration` scripts.
- **How:** Test commit first (red: the fixtures at 0.5/1.9/2.1/5 km returned nothing), then the implementation commit (green). The test builds our own image, runs the real migrations, and queries real PostGIS.
- **Why:** Raw `pg` with plain SQL because the key queries are spatial; Prisma/Drizzle would not remove them. Two forced deviations: `postgis/postgis:17-3.5` is Debian 11 with a dead PGDG apt repo, so pgvector could not be installed; used `18-3.6`. `testcontainers` 12 needs Node 22, so pinned 11.14 to keep Node 20.
- **Learn:** `geography` measures in metres on the earth's surface and `ST_DWithin` uses the GiST index, so it filters first; `ST_Distance` then only runs on the few rows left. Point order is (longitude, latitude).
