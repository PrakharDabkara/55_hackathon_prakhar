# 2026-10-13

## Day 2 CI and data

- **What:** Postgres (PostGIS + pgvector) and Redis in `docker-compose.yml` with `infra/postgres/Dockerfile`; SQL migrations for extensions and `shops` (GiST index); ADR-0007; `findShopsWithinRadius` with a Testcontainers test; `.github/workflows/ci.yml`, `.nvmrc`, `tsconfig.json`; `db:*`, `typecheck`, `test:unit`, `test:integration` scripts.
- **How:** Test commit first (red: the fixtures at 0.5/1.9/2.1/5 km returned nothing), then the implementation commit (green). The test builds our own image, runs the real migrations, and queries real PostGIS.
- **Why:** Raw `pg` with plain SQL because the key queries are spatial; Prisma/Drizzle would not remove them. Two forced deviations: `postgis/postgis:17-3.5` is Debian 11 with a dead PGDG apt repo, so pgvector could not be installed; used `18-3.6`. `testcontainers` 12 needs Node 22, so pinned 11.14 to keep Node 20.
- **Learn:** `geography` measures in metres on the earth's surface and `ST_DWithin` uses the GiST index, so it filters first; `ST_Distance` then only runs on the few rows left. Point order is (longitude, latitude).

## Move to Node 24

- **What:** `.nvmrc` and `engines` to Node 24, `testcontainers` and `@testcontainers/postgresql` to 12.2.0, ADR-0008, BRIEF decisions row and Day 1–2 ticked. Branch `chore-node-24`.
- **How:** Installed Node 24 with nvm, bumped the packages, reinstalled from scratch with `npm ci`, ran lint, typecheck, unit and integration tests. CI reads `.nvmrc`, so it needed no edit.
- **Why:** Node 20 is end of life, and the older Testcontainers pin was only there for Node 20. Rejected keeping Node 20 with a pinned old library: it leaves both unsupported.
- **Learn:** `node-version-file: .nvmrc` makes one file the single source of the Node version for local and CI.

## Day 3 deploy skeleton (free tier)

- **What:** API skeleton in `apps/api/src` (`config/`, `http/`, `app.ts`, `shutdown.ts`, `server.ts`); `infra/api/Dockerfile`, `.dockerignore`, `render.yaml`; `deploy` job in `ci.yml`; `apps/api/scripts/redis-idle-worker.ts`; ADR-0009, ADR-0010, runbook v1; BRIEF cloud row and Day 3 updated.
- **How:** Tests first (23 red), then code. Built the image, ran it against compose Postgres: `/health` 200, `/ready` 200, `/ready` 503 with the database stopped, SIGTERM exits 0. Ran an idle BullMQ worker for 10 minutes against local Redis and read `INFO commandstats`.
- **Why:** The idle worker made 2 commands/s, about 5.2M a month, 10x Upstash's 500K cap, so Render Key Value won (ADR-0010). `ioredis` was added with your OK because BullMQ 6 made it a peer dependency. Rejected a separate deploy workflow: a `needs: ci` job guarantees "after CI passes" with less indirection.
- **Learn:** Liveness (`/health`, no dependencies) and readiness (`/ready`, checks the database) answer different questions. Mixing them makes a database blip restart a healthy process.
