# 2026-10-18 · Day 15, PR A: the holdout found a hole in "real product or nonsense"

- **What:** The first resolve holdout run failed its nonsense gate (7/8): one nonsense query was made into a new user item. The dev run also had one plain miss (a bead kit matched the catalog item "glitter" at the LLM step). Fixed: a confidence from the classifier (create only when real and confident), free code checks before the model, a clearer "not understood" message, and a resolve-prompt rule against loose relations.
- **How:** From the CI log I took only the failure mode of the holdout case (stage `new_item`, not a catalog match), masking its text. I wrote 18 new dev cases myself (random strings, keyboard mash, real words that are not products, a person, a place, a service, vehicles and phones) and wrote the tests first.
- **Why, honestly:** The holdout exposed this; the dev set had not, because its nonsense cases were easy. The fix is a general rule ("when unsure, do not create") written against new dev cases, not against the holdout case. Rejected: a blocklist for the failing text, and lowering the gate.
- **Learn:** A model asked "is this real?" will say yes to plausible-looking text. Ask for confidence, require "real and confident", and put cheap deterministic checks in front; the default for doubt must be the harmless outcome.

# 2026-10-18 · The simulator test was a coin toss

- **What:** `simulate.int.test.ts` failed in CI on PR #31 about one run in fifty. Cause confirmed by simulation: with random reply profiles and category-aware answers, 40 of 2,000 seeds leave every shop that sells flour silent or saying no. Fixed by a fixed seed, eager answers, an assertion that at least three sellers exist, and a second test for the "no" outside the category. The shop mix is now dealt from a deck so a street always has every kind.
- **Honest note:** I pushed the first fix straight to main by mistake (wrong branch); this one went through a branch.
- **Learn:** A test that uses randomness for something it is not about will fail in CI sooner or later: fix the seed, or take the choice away.

# 2026-10-18 · Day 16, PR D: delivery orders

- **What:** migration 017 and the `orders` module (guarded state machine, views, expiry sweep, routes), pickup fallback through the errands and requests public indexes, the configured fewer-stops limit after a delivery choice, `ping.closed` reasons, simulator order handling, customer order panel and shop order cards, a thanks note for a withdrawn question, an e2e at 360 px (full order, and a decline), ADR-0032.
- **How:** Red commits first for the API, simulator and web; then the code. Privacy is built into the view functions (field by field) and checked by a test that searches every other table, the logs and the events for the address.
