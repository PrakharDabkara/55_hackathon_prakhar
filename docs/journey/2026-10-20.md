# 2026-10-20 · PR #43 CI fixes

- **What:** Find no longer flashes the address field and then removes it (`apps/web/src/screens/Home.tsx`, test in `Home.test.tsx`); `e2e/orderFlow.ts` `ask` types only into the field; `demand.spec.ts` waits for Insights to load; `customer-screens.spec.ts` has a 90 s limit, no retries, 360 px scans and `SCREENS=1` screenshots; `e2e/.auth/` is in `.gitignore`.
- **How:** Red unit test first (a kept address must never show a typing field), then a `savedLoaded` state with a skeleton until the request answers. The full e2e ran locally with fresh phones: 21 passed in 2m31s.
- **Why:** The old code showed the field while the saved-address request was pending, so a customer who had ordered before lost the field under `fill()` once the answer came (slow in CI, fast locally). Rejected: a longer Playwright timeout, which hides the race from real users too.
- **Learn:** A UI that shows something before it knows the answer and then swaps it is a race the user can lose; render "unknown" as its own state.

# 2026-10-20 · PR N: collect up to three offers (ADR-0043)

- **What:** `MAX_LIVE_OFFERS = 3` in `modules/requests` (`pings.ts`, `persistence.ts`, `events.ts`); orders and pickups withdraw the still-open pings; catch-up and the shop's ping list include ANSWERED requests; `liveOffers.int.test.ts` (S22-S26); `customer-screens.spec.ts` seeds three live yes and one late; the flaky `App.test.tsx` offline test.
- **How:** Red tests first, then the cap rides on the request row lock `answerPing` already takes: count live yes after the guarded UPDATE, at 3 withdraw the open pings. `applyEventIn` withdraws for every event but a yes. Old tests that assumed "first yes closes" were rewritten; two files also close ANSWERED requests between tests because a new shop is now caught up on them.
- **Why:** Counting under the existing lock makes the 3rd/4th race safe without a new lock; rejected a counter column (needs a migration and can drift). The offline test now waits for the shell's first load before sending the event; I could not reproduce the flake locally (30 runs under load), so the cause (event sent before the effect that listens runs) is read from React/RTL timing, not observed. Not run locally: the full e2e, because it writes to the database in `.env`; CI runs it.
- **Learn:** Serialise with the lock you already hold and put the counting in the same transaction; "at most N" rules then need no extra coordination.
