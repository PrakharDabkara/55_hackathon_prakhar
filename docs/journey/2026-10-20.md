# 2026-10-20 · PR #43 CI fixes

- **What:** Find no longer flashes the address field and then removes it (`apps/web/src/screens/Home.tsx`, test in `Home.test.tsx`); `e2e/orderFlow.ts` `ask` types only into the field; `demand.spec.ts` waits for Insights to load; `customer-screens.spec.ts` has a 90 s limit, no retries, 360 px scans and `SCREENS=1` screenshots; `e2e/.auth/` is in `.gitignore`.
- **How:** Red unit test first (a kept address must never show a typing field), then a `savedLoaded` state with a skeleton until the request answers. The full e2e ran locally with fresh phones: 21 passed in 2m31s.
- **Why:** The old code showed the field while the saved-address request was pending, so a customer who had ordered before lost the field under `fill()` once the answer came (slow in CI, fast locally). Rejected: a longer Playwright timeout, which hides the race from real users too.
- **Learn:** A UI that shows something before it knows the answer and then swaps it is a race the user can lose; render "unknown" as its own state.
