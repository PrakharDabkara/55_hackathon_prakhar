## PR R1: run unattended 24/7 until Nov 6

- **What:** every queue now has one retention policy (`workers/jobRetention.ts`); start-up clean-up of old completed jobs; Redis memory in `/admin/health/details` and `release-check.sh`; idle-query perf fixed and ADR-0062 corrected; runbook section and ADR-0064.
- **How:** tests first (Testcontainers Redis), then `defaultJobOptions` on all five queues and in the sweep scheduler template, `queue.clean` in capped batches, `INFO memory` on a short-leashed connection.

## PR F1: failure modes, assumed vs observed

- **How:** listed every external-failure branch, pulled error lines from 16 CI dev runs, recorded Redis/Postgres failures from Testcontainers, replayed them through the real code. No app code changed.

## PR test/eval-and-flake-fixes: eval harness, docs, truncate deadlock

- **What:** `evalRetry.ts` (+test) used by `evalResolveMain.ts`; `testing/truncate.ts` (retry on 40P01), `testing/waitForQuietDb.ts`, `testing/truncate.test.ts`, `demoAutopilot.int.test.ts` afterEach; `docs/evals.md`, CHANGELOG. No app runtime code.
- **How:** the eval-analyst read the dev runs (errand p95 came from 503s and 30 s timeouts on the tool-side 3.1 model, not R2). Tests first for the retry counter and the truncate helpers. The deadlock did not reproduce locally (0/30 idle and 0/30 under load, before and after), so the fix is defensive, from the CI log and the un-awaited `catchUp()`.
- **Why:** per-attempt failure counts, so a recovered retry is not an error. d18 stays a known miss: changing a case until the model passes is tuning. Rejected: locking tables up front (still deadlocks if the other side holds the first one).
- **Learn:** a `void promise` at startup outlives `close()`; the next test's truncate then queues behind its reads, and Postgres ends the cycle by cancelling one side (40P01), which is safe to retry.
