# 2026-10-24

## PR R1: run unattended 24/7 until Nov 6

- **What:** every queue now has one retention policy (`workers/jobRetention.ts`); start-up clean-up of old completed jobs; Redis memory in `/admin/health/details` and `release-check.sh`; idle-query perf fixed and ADR-0062 corrected; runbook section and ADR-0064.
- **How:** tests first (Testcontainers Redis), then `defaultJobOptions` on all five queues and in the sweep scheduler template, `queue.clean` in capped batches, `INFO memory` on a short-leashed connection.
- **Why:** the sweep job scheduler kept 1,440 finished jobs a day in a 25 MB `noeviction` Redis. Rejected: only patching the sweep (next queue leaks again), Redis eviction (drops live jobs).
- **Learn:** a BullMQ scheduler's jobs take their options from the template and the queue defaults, not from the `add` calls around it; "no limit" is the default, not "clean up after itself".

## PR F1: failure modes, assumed vs observed

- **What:** `docs/failure-modes.md`; observed fixtures (`apps/api/src/testing/observed/`); contract tests for Gemini, Redis, Postgres and the demo lock; two probe scripts for the owner to run with the evals key.
- **How:** listed every external-failure branch, pulled error lines from 16 CI dev runs, recorded Redis/Postgres failures from Testcontainers, replayed them through the real code. No app code changed.
- **Why:** the daily-vs-minute 429 split rested on a guessed body; the only real 429 had no such hint. Rejected: fixing bugs in the same PR (R2 does that).
- **Learn:** Redis `noeviction` refuses new-key writes, not all writes: `INCR` of an existing key still passes at the limit, and a checked-out `pg` client needs its own `error` listener because the Pool only watches idle ones.
